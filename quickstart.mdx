Here's the fastest way to see what getrequest actually does: create an endpoint, send it a request, and watch that request make the round trip. This walkthrough uses a retail checkout call — a case where the caller needs your real response back — but every step here works identically for any endpoint you create.

## Step 1: Create an endpoint

1. Sign in to [app.getrequest.io](https://app.getrequest.io) and open your project.
2. Click **New Endpoint**.
3. Fill in the fields:

| Field | Example | Notes |
|-------|---------|-------|
| Name | `Order checkout` | Human-readable label |
| Slug | `/orders/checkout` | Appended to your project URL |
| Method | `POST` | Choose one or more: GET, POST, PUT, PATCH, DELETE |
| Action | `Sync API` | Proxies inline and returns your destination's exact response |
| Destination URL | `https://postman-echo.com/post` | A public echo endpoint, so this walkthrough works without a backend of your own |

4. Click **Create**. Your endpoint is live immediately.

Your endpoint URL will look like this:

```
https://e.getrequest.io/ddfkU760XMs2z7te/orders/checkout
```

<Note>
  Your project URI (`ddfkU760XMs2z7te` above) is unique to your project. Copy it from the project page.
</Note>

## Step 2: Send your first request

Simulate a checkout request:

<CodeGroup>

```bash cURL
curl -X POST https://e.getrequest.io/{project_uri}/orders/checkout \
  -H "Content-Type: application/json" \
  -d '{
    "order_id": "ord_8841",
    "items": [{ "sku": "SKU-123", "qty": 2 }],
    "total": 59.98
  }'
```

```javascript JavaScript
const response = await fetch('https://e.getrequest.io/{project_uri}/orders/checkout', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({
    order_id: 'ord_8841',
    items: [{ sku: 'SKU-123', qty: 2 }],
    total: 59.98,
  }),
});

const data = await response.json();
console.log(data);
```

```python Python
import requests

response = requests.post(
    'https://e.getrequest.io/{project_uri}/orders/checkout',
    headers={
        'Content-Type': 'application/json',
    },
    json={
        'order_id': 'ord_8841',
        'items': [{'sku': 'SKU-123', 'qty': 2}],
        'total': 59.98,
    },
)

print(response.json())
```

```php PHP
$client = new \GuzzleHttp\Client();

$response = $client->post('https://e.getrequest.io/{project_uri}/orders/checkout', [
    'headers' => [
        'Content-Type' => 'application/json',
    ],
    'json' => [
        'order_id' => 'ord_8841',
        'items' => [['sku' => 'SKU-123', 'qty' => 2]],
        'total' => 59.98,
    ],
]);

echo $response->getBody();
```

</CodeGroup>

Because this is a **Sync API** endpoint, you get back the destination's exact response — not something getrequest invents. `postman-echo.com` echoes whatever it received, so the response looks like this:

```json
{
  "args": {},
  "data": "",
  "json": {
    "order_id": "ord_8841",
    "items": [{ "sku": "SKU-123", "qty": 2 }],
    "total": 59.98
  },
  "headers": { "...": "..." },
  "url": "https://postman-echo.com/post"
}
```

That `json` field is your original payload, sent back unchanged — proof that getrequest proxied it through untouched. Point the **Destination URL** at your own backend instead, and this same response would be whatever *your* backend returns.

getrequest didn't just relay that request, though — it also kept a copy. That's what the next step shows you.

---

## Step 3: Verify the request arrived

Open your project in the dashboard and click **Logs**.

You'll see the request you just sent — method, status, path, and duration. Click the row to inspect:

- **Request** — full headers, query params, and body
- **Response** — status code, headers, and body
- **Timing** — how long it took end to end

This is exactly what getrequest captures for every request it receives. Nothing is dropped, even before your backend ever sees it.

<Tip>
  On paid plans, you can click **Share** on any log entry to generate a public link — useful for bug reports and team debugging. See the [FAQ](/faq) for which plans.
</Tip>

---

You just sent a real request through getrequest, got your destination's exact response back, and watched the whole exchange land in Logs — no code, no config file, no redeploy. The next step is pointing this at your real backend instead of a public echo endpoint, and deciding how you want getrequest to behave when it gets there: wait for the response like you just did, hand it off in the background, or skip the backend entirely with a mock.
