getrequest sits in front of any backend as an API reliability layer — so traffic spikes, downtime, or failed deployments never result in lost requests.

## The problem it solves

When your backend goes down, requests vanish. There's no record of what came in, no way to recover what was lost, and your users have already moved on.

getrequest fixes this at the infrastructure level — before the request ever reaches your code.

## How it works

You create an **endpoint** in getrequest — no code, no deploy. getrequest gives you a URL:

```
https://e.getrequest.io/{project_uri}/{your-slug}
```

Point your callers at that URL, and getrequest starts capturing every request that arrives — before it decides what to do with it. What it does next is up to you.

## Three endpoint types

| Type | What it does | When to use |
|------|-------------|-------------|
| **Sync API** | Proxies the request to your destination and returns its exact response, inline | Production traffic where the caller needs your real response |
| **Async API** | Acknowledges the caller immediately, then delivers to your destination in the background with automatic retries | Webhooks and any fire-and-forget delivery |
| **Static API** | Returns a static JSON payload you define | Mocking, local dev, frontend unblocking |

You can switch between them at any time — zero downtime, no redeployment. Not sure which one you need? [Sync vs. Async endpoints](/guides/async-api) walks through exactly when to reach for each.

## Built-in authentication

Whichever type you pick, you can lock down who's allowed to use it. Every endpoint can require a credential on incoming requests, and can attach a credential to its own outbound destination call — two independent, per-endpoint settings, nothing to code. See [Authenticate endpoints and destinations](/guides/authentication).

That's the whole model: one URL, a type that decides what happens when a request hits it, and logging that never turns off. The rest of these docs go deeper on each piece — but you'll understand it fastest by just doing it.
